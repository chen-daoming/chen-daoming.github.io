"串口"这个词在日常交流里至少混着三种东西：芯片脚上直接出来的 TTL、老设备背后的 DB9 RS232、工业柜子里的 A/B 两根线 RS485。它们协议层完全兼容（同样的 UART 帧），物理层却天差地别——**直接对插轻则乱码，重则烧口**。这篇笔记把三种接口的电平标准、波形长相、转换电路讲清，并给出我实际在用的 RS485 方向控制驱动和 CRC16 校验代码，以及一套"三种电平一网打尽"的调试硬件清单。

## 一、三种接口的定位：先分清用在哪

![三种串行接口的定位](/images/uart-levels/01-uart-family.svg)

| 维度 | TTL | RS232 | RS485 |
|---|---|---|---|
| 电平 | 0 / 3.3V（或 5V） | ±3 ~ ±15V | 差分 A−B |
| 逻辑 | 正逻辑（高=1） | **负逻辑（负电压=1）** | A−B > +200mV = 1 |
| 距离 | ≤ 1~2m | ≤ 15m @ 9600bps | ≤ 1200m @ 100kbps |
| 拓扑 | 点对点 | 点对点 | 总线（半双工 2 线 / 全双工 4 线） |
| 节点数 | 1 对 1 | 1 对 1 | 32 个标准负载（1/8 负载可到 256） |
| 抗干扰 | 弱（单端、共地） | 中（摆幅大） | 强（差分共模抑制 −7~+12V） |

一句话：**TTL 是"裸"的芯片电平，出了板子就该穿衣服——短途穿 RS232，长途穿 RS485**。

## 二、波形对比：同一段数据的三种长相

![同一段数据在三种电平标准下的波形](/images/uart-levels/02-level-waveforms.svg)

拿 `0x55`（位序 1,0,1,0,1,0,1,0，LSB 先行）做例子，三个要点看图即懂：

1. **TTL**：0V=0、3.3V=1，和芯片引脚一模一样。注意 3.3V 与 5V 系统**不能直连**：5V 系统的输出高电平接近 5V，超出 3.3V 引脚耐压，需要电平转换或开漏+上拉；
2. **RS232**：波形和 TTL **上下反相**——它用负电压表示 1！这是历史上最坑人的约定，用示波器第一次看 RS232 波形"反的"以为坏了，其实是标准如此；
3. **RS485**：一根线看不懂，必须 A、B 两根一起看，判决的是**差值** A−B。这也是它能跑 1200 米的底气：干扰同时耦合到 A、B 两根线，一相减就被抵消（共模抑制）。

## 三、RS485 组网：端接、偏置与半双工

![RS485 总线拓扑](/images/uart-levels/03-rs485-bus.svg)

RS485 是总线，布线规则比选芯片更重要：

- **拓扑**：手拉手菊花链。星形、树形分支会产生反射，长线下是事故源头；
- **端接**：只在**总线两端**并 120Ω（与双绞线特征阻抗匹配）。短线（几米内）可以省；中间节点加端接是新手高频错误，并联过度会把差分摆幅拉塌；
- **失效保护**：总线空闲时没有任何驱动，A−B 接近 0V，处于判决死区——在主机侧 A 上拉到 VCC、B 下拉到 GND（560Ω~1kΩ 偏置电阻），或在收发器里选带 Fail-Safe 的型号（如 SP3485、MAX3485 系列）；
- **半双工方向控制**：2 线制同一时刻只能有一个节点发送，DE/RE 引脚由 GPIO 控制，切换时机的坑见第五节代码。

## 四、电平转换：MAX3232 与 MAX485

![MAX3232 与 MAX485 应用电路](/images/uart-levels/04-converter-circuit.svg)

选型速查：

- **RS232**：3.3V 系统用 MAX3232 / SP3232（内置电荷泵自己造 ±电压），**4 颗飞跨电容 + 1 颗电源退耦，一颗都不能省**，否则泵压不足输出摆幅不够；
- **RS485**：5V 用 MAX485，3.3V 用 MAX3485 / SP3485；隔离场景选 ADM2483 / ISO3082 这类磁隔离收发器，工业现场 A/B 对地各挂一颗 TVS（如 SMBJ6.8CA，原理见上一篇防护笔记的做法）；
- **接线**：TTL 侧 TX↔RX 交叉；RS485 侧 **A 接 A、B 接 B，不交叉**（不同厂家丝印有 A/B 标反的传统，实在不通就对调一次）；

## 五、原创代码：RS485 方向控制 + CRC16

### 1. 方向控制：等 TC 标志，别等 CpltCallback

半双工 RS485 最经典的 bug 是**帧尾丢字节**：用 `HAL_UART_TxCpltCallback` 里拉低 DE，看似没问题，但 Cplt 触发时最后一个字节可能还停在移位寄存器里没发出去。正确做法是等 **TC（Transmission Complete）标志**——它表示移位寄存器也空了：

```c
/* rs485.c —— 半双工方向控制驱动（HAL 库，原创实现） */
#include "rs485.h"
#include <string.h>

#define RS485_UART   huart2        /* 挂 MAX485 的串口 */
#define RS485_DE_PORT GPIOA
#define RS485_DE_PIN  GPIO_PIN_8   /* DE、RE 并联在同一 GPIO */

/* 发送前 DE 拉高；等 TC（移位寄存器空）再拉低 */
void RS485_Send(const uint8_t *buf, uint16_t len)
{
    HAL_GPIO_WritePin(RS485_DE_PORT, RS485_DE_PIN, GPIO_PIN_SET);   /* 占线 */

    HAL_UART_Transmit(&RS485_UART, (uint8_t *)buf, len, 100);

    /* 关键：轮询 TC 而不是 Cplt —— TC 置位时最后一位已完整移出 */
    while (__HAL_UART_GET_FLAG(&RS485_UART, UART_FLAG_TC) == RESET) { }
    HAL_GPIO_WritePin(RS485_DE_PORT, RS485_DE_PIN, GPIO_PIN_RESET); /* 交还总线 */
}
```

工程化版本（DMA + 空闲中断）思路相同：`HAL_UART_Transmit_DMA` 启动后，在 TC 中断里拉低 DE；结构上把"方向"封装进发送函数，调用者永远不用碰 DE。

### 2. CRC16-Modbus：RS485 组网标配校验

多机总线上靠地址 + 校验防误收，Modbus RTU 用的 CRC16 是必会手写项（查表法更快，位翻法更省 RAM，下面是省 RAM 版）：

```c
/* crc16.c —— CRC16/MODBUS: 初值 0xFFFF, 多项式 0x8005(反转 0xA001) */
uint16_t CRC16_Modbus(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFF;

    for (uint16_t i = 0; i < len; i++) {
        crc ^= data[i];                       /* 低字节先入 */
        for (uint8_t j = 0; j < 8; j++) {
            if (crc & 0x0001)  crc = (crc >> 1) ^ 0xA001;
            else               crc >>= 1;
        }
    }
    return crc;   /* 低字节在前发送（与 Modbus 一致） */
}

/* 发送一帧：从机地址 + 功能码 + 数据 + CRC */
void RS485_SendFrame(uint8_t addr, uint8_t func,
                     const uint8_t *payload, uint16_t len)
{
    uint8_t  buf[64];
    uint16_t crc;

    buf[0] = addr; buf[1] = func;
    memcpy(&buf[2], payload, len);
    crc = CRC16_Modbus(buf, len + 2);
    buf[len + 2] = crc & 0xFF;          /* CRC 低字节在前 */
    buf[len + 3] = (crc >> 8) & 0xFF;
    RS485_Send(buf, len + 4);
}
```

这两段代码在我的 RS485 温度采集网上跑了一年没出过帧错误，抄走就能用。

## 六、配套调试硬件清单

| 硬件 | 数量 | 用途 |
|---|---|---|
| USB 转 TTL（CH340） | 1 | 直接看 TTL 电平 |
| USB 转 232（FT232RL+MAX3232） | 1 | RS232 侧抓包 |
| USB 转 485（带隔离更佳） | 2 | 双端监控总线，一个当主机一个抓线 |
| MAX485 模块 / MAX3232 模块 | 各 2 | 自制转换板 |
| 示波器（双通道以上） | 1 | 看 A/B 差分波形与方向切换时序 |
| 120Ω 电阻、双绞线 | 若干 | 端接与长线实验（网线里抽一对就行） |

**硬件实验路线**：先用 USB 转 TTL 直连小蓝板确认协议层 → 插 MAX3232 看 RS232 反相波形 → 再切 MAX485，两块板一条 100 米网线双绞线，把 CRC16 打开跑整夜，统计误码率——三种电平一晚上全部体感一遍。

## 七、常见坑速查

| 现象 | 根因 | 处理 |
|---|---|---|
| RS232 乱码但波形"正常" | 忘了负逻辑，以为反相是故障 | 波形反相才是对的 |
| 3.3V 与 5V TTL 直连乱码/发烫 | 电平不兼容 | 电平转换芯片或开漏+上拉 |
| RS485 帧尾丢字节、CRC 报错 | DE 拉低太早（没用 TC） | 等移位寄存器空，见第五节 |
| 总线闲置时读数乱跳 | A−B 落在 ±200mV 死区 | 主机侧加偏置电阻 / 选 Fail-Safe 收发器 |
| 长线通信偶发错包 | 未端接、有星形分支 | 两端 120Ω，改菊花链 |
| A/B 接反不通 | 各厂丝印习惯不同 | 交换 A/B 再试 |
| 多机偶尔"幻听" | 无 CRC / 无地址过滤 | 加 CRC16 + 帧头地址过滤 |

## 八、小结

三种接口一条主线：**越恶劣的环境，越要"离地"传输**——TTL 共地共电源最娇气，RS232 靠大摆幅，RS485 靠差分。选接口先看距离和节点数，选芯片先看供电电压，写驱动先解决半双工方向时序，最后用 CRC 给数据兜底。掌握这套组合拳，串口问题基本可以"看一眼波形就定位"。
